# Campaign & Weekly Planning Principles

Read `context/hard-rules.md` and `context/accounts.md` first. This file is for the `/strategy`
skill's `campaign-planner` agent — sequencing knowledge for turning a strategic goal into a
day-by-day (or phase-by-phase) content calendar, not copy-drafting rules.

## Narrative arc

A strong week (or campaign) tells a story across days, not a pile of unrelated posts. A reliable
shape:

1. **Tension** — name the real problem, no company name yet. Sets up why anyone should care.
2. **Wedge / mechanism** — the specific angle Ratel has on that problem. Concrete, not abstract.
3. **Proof** — a benchmark, a client result, a demo. Only schedule this once the benchmark page is
   confirmed live (`context/hard-rules.md`) or once a client has explicitly signed off on
   disclosure — flag in the plan if proof-day content depends on a confirmation that hasn't
   happened yet, don't silently assume it will land in time.
4. **People** — founder or team voice, personal stakes, origin story. Builds trust after the
   technical claims land.
5. **Open question / CTA** — lower-pressure close: an invitation to discuss, not a hard sell.

Not every week needs all five beats. A routine (non-campaign) week can just pick 2-3 content
`Type`s from the Notion schema (Problem, Solution, Benchmarks, People, Product, Event) that make
sense together, without forcing a full arc.

## Cadence and platform mix

- **LinkedIn**: 3-5x/week. Don't schedule LinkedIn content on every single day by default — it
  reads as noise. Space it out.
- **X**: can run more frequently, up to daily, since the platform rewards a higher-frequency raw
  posting cadence (see `context/x-style.md`).
- **Reddit**: only schedule it when there's a genuine technical/community-fit angle for a specific
  subreddit (see `context/reddit-style.md`'s rubric) — not a default inclusion every day. A week
  with zero Reddit posts is normal; forcing one in just to "cover all platforms" produces a weak
  post that gets removed or ignored.
- **Don't repeat the same `Type`** (Problem/Solution/Benchmarks/People/Product/Event) on
  back-to-back scheduled days — it flattens the arc and reads as repetitive even across platforms.
- **Cross-platform coordination for big moments** (a launch, a benchmark reveal, a major release):
  it's fine, often correct, to schedule the same day on multiple platforms at once, each with
  distinct framing per platform's voice (see the style files) rather than the same copy pasted
  across all three. Routine weeks don't need this — one platform per day is normal.
- **Personal-profile posts** (founder voice, `Linkedin Rob`/`Linkedin Giac`/`X Rob`/`X Giac`) pair
  well same-day with a main-channel technical or launch post, as support/amplification, not as a
  replacement for it.

## Check the existing pipeline before planning

Always query the Notion database for what's already scheduled in the target date range before
proposing new slots — never propose a day that already has a post planned without either building
around it or explicitly flagging the conflict to the user.

## What this file is not

This is sequencing guidance, not copy-drafting rules (see the `*-style.md` files) and not the hard
gate list (see `hard-rules.md`). A campaign plan that schedules a "Benchmarks" post before the
benchmark page is confirmed live is a planning error even if every individual post, once drafted,
would follow the style bible correctly.
